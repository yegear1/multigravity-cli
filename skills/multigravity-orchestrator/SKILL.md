# Multigravity Orchestrator (`multigravity-orchestrator`)

Canonical playbook for autonomous AI agents (Antigravity IDE, Cursor, Claude Code, Aider) to decompose complex software engineering tasks into Directed Acyclic Graphs (DAGs), allocate worker tasks across isolated Multigravity profiles based on real-time quota telemetry, and safely govern ephemeral Git worktree lifecycles and merge pipelines.

## 1. Scope & Blast Radius

- **MUTABLE PATHS:**
  - Ephemeral task worktrees: `.multigravity/worktrees/<task-id>/` (configured via Git include/exclude).
  - Task manifests and execution metadata: `.multigravity/tasks/<task-id>/task.json` and `run.log`.
  - Temporary integration/feature git branches (e.g., `feat/<feature>-<task-id>`).
  - Target project working tree during approved merge steps only.
- **IMMUTABLE PATHS:**
  - Host dotfiles: `$REAL_HOME/.gitconfig`, `$REAL_HOME/.ssh/`, `$REAL_HOME/.config/gh/`.
  - Profile authentication vaults: `<profile>/.gemini/antigravity-oauth-token`, `<profile>/.gemini/jetski-standalone-oauth-token`.
  - Active profile storage directories outside ephemeral worktrees (`$MULTIGRAVITY_HOME/<profile>/`).
  - Main repository branch when uncommitted changes exist (dirty working tree).
- **FORBIDDEN ACTIONS:**
  - MUST NOT dispatch tasks to any profile whose measured remaining quota fraction is $\le 0.05$ (5%) or currently under provider rate-limit cooldown.
  - MUST NOT perform parallel tasks modifying the same file paths across concurrent worktrees (overlapping blast radius).
  - MUST NOT merge worktree branches into the base branch without running and passing automated test suites (`go test`, unit tests, linters) inside the worktree first.
  - MUST NOT execute destructive actions (`git merge --strategy=ours`, `git push --force`, `rm -rf`) during merge conflict resolution.
  - MUST NOT delete or prune worktrees while associated task sessions are in `running` or `pending` status.
  - MUST NOT copy or share authentication tokens between profiles or worker sessions.

## 2. When to Use (Triggers)

The agent MUST activate this skill when:
- Executing complex, multi-file or multi-step tasks that can be broken into independent or staged subtasks.
- Operating in a multi-profile environment where quota capacity needs to be balanced across multiple accounts (Gemini 5h/weekly, 3P 5h/weekly).
- Dispatching background worker agents (Claude Code CLI, Aider, OpenCode, headless agy) in isolated Git worktrees.
- Monitoring and synchronizing asynchronous tasks across multiple worker sessions.
- Merging and reconciling changes generated by parallel worker agents back into the primary codebase.

The agent MUST NOT activate this skill when:
- Performing simple, single-file edits or localized bugfixes that fit comfortably in a single agent turn.
- Querying host metrics or server container logs (activate `homelab-inspector` or `victorialogs-troubleshooting`).
- Creating or managing basic Antigravity profile configuration and dotfiles sharing (activate `multigravity`).

## 3. Required Tools & Prerequisites

- **Tools:** `multigravity` (executable in `$PATH` or `./bin/multigravity`), `git` (2.25+ with worktree support), `bash` (4.0+), optional `jq` or native MCP server (`multigravity mcp serve`).
- **Prerequisites:**
  - The target git repository must have a clean working directory before provisioning worktrees (`git -C "$REPO" status --porcelain` is empty). The agent workspace may be a different repository.
  - Multigravity daemon is accessible via CLI, or HTTP API (`127.0.0.1:8989`), or MCP stdio/HTTP.
  - At least one healthy, authenticated profile with $\text{remaining\_fraction} > 0.05$.

## 4. Multi-Agent DAG Topology & Mental Model

Decompose engineering objectives into a Directed Acyclic Graph (DAG) with explicit stage gating:

```text
       [Stage 0: Analysis & Contract Definition]
                          │
          ┌───────────────┴───────────────┐
          ▼                               ▼
[Stage 1A: Worker Alpha]        [Stage 1B: Worker Beta]
(Profile: dev1, Worktree A)     (Profile: dev2, Worktree B)
(Scope: backend/internal/)      (Scope: frontend/ui/)
          │                               │
          └───────────────┬───────────────┘
                          ▼
        [Stage 2: Integration & Verification]
        (Profile: dev-test, Worktree Integration)
                          │
                          ▼
       [Stage 3: Topological Merge & Teardown]
```

### Node Constraints & Partitioning Rules
1. **Disjoint Scope Rule:** Parallel worker nodes scheduled concurrently MUST have mutually exclusive file sets. If Node A touches `pkg/foo`, Node B MUST NOT touch `pkg/foo`.
2. **Contract-First Rule:** If Node B depends on interfaces produced by Node A, Node A MUST complete and publish interface schemas or stubs before Node B is dispatched.
3. **Fail-Fast Barrier:** If any node in Stage $N$ fails its internal test suite, all dependent nodes in Stage $N+1$ MUST be paused or cancelled immediately.

## 5. Quota-Aware Profile Routing Matrix

Evaluate profile quota telemetry before assigning each task node.

### Telemetry Inspection
Query quota state using CLI or native MCP:
```bash
# Via CLI
multigravity quota --json
multigravity alerts --json

# Or via Native MCP Tools
# tools/call: quota_summary {}
# tools/call: alerts_list {}
```

### Allocation Rules
| Quota Indicator | Condition | Routing Decision |
| :--- | :--- | :--- |
| **Critical Quota** | `remaining_fraction <= 0.05` | **BLOCKED.** Do not assign any worker. Wait for reset or prime. |
| **Active Cooldown** | `cooldown_until > now` | **BLOCKED.** Profile hit HTTP 429/403. Route to alternate profile. |
| **5h Window Available** | `windowType == "5h"` and `remaining_fraction >= 0.50` | **ASSIGN.** High-priority for bursty, token-dense generation tasks. |
| **Weekly Window Only** | `windowType == "weekly"` and `remaining_fraction >= 0.30` | **ASSIGN.** Medium/large architectural tasks. Conserve if < 30%. |
| **Idle 5h Refresh** | `canWarm5hWindow == true` | **TRIGGER WARM-UP.** Run `multigravity prime <profile> --warm-5h` before starting task. |

## 6. Operational Execution Protocol

A git diff that will be merged uses `dispatch` in every phase below. Any other outcome uses the first matching row in `skills/multigravity/SKILL.md` (Runner Selection). This skill does not switch a merge to `exec`, `headless run`, `agent run`, or `prime`.

### Phase 1: Task Decomposition & DAG Definition
1. Analyze the user request, affected repositories, and target architectural boundaries.
2. Identify independent components vs sequential prerequisites.
3. Partition target file paths into disjoint sets per subtask.
4. Record the planned DAG in your working memory:
   - Node ID, Target Profile, Dependent Node IDs (`depends_on`), Disjoint Scope Paths, Prompt Specification.

### Phase 2: Quota Pre-Flight & Profile Allocation
1. Fetch live quotas across all registered profiles:
   ```bash
   multigravity quota --json
   ```
2. Filter profiles with valid authentication (`multigravity login status <profile> --json`) and healthy quota (`remaining_fraction > 0.05`).
3. Map DAG nodes to candidate profiles ensuring balanced utilization.

### Phase 3: Ephemeral Worktree Provisioning & Worker Dispatch
1. Resolve the target repository and require a clean worktree there. Do not change the agent workspace to do this:
   ```bash
   REPO=$(git -C "<target>" rev-parse --show-toplevel)
   git -C "$REPO" status --porcelain
   ```
   *If porcelain is non-empty: stash or commit inside `$REPO` before proceeding.*
2. Stay in the current workspace and pass that absolute path as `--repo` (CLI) or `repo` (MCP `dispatch_plan`). `move_agent_to_root` runs `git fetch origin <branch>` and aborts the turn when the target has no `origin`, so no worker starts.
   ```bash
   if ! git -C "$REPO" remote get-url origin >/dev/null 2>&1; then
     echo "no origin: dispatch with --repo; do not move the IDE root"
   fi
   ```
   A missing `origin` forbids `move_agent_to_root`. Switch the IDE root only after the plan returns, and only when a human will keep editing that tree in the IDE.
3. Dispatch independent worker tasks into isolated Git worktrees:
   ```bash
   # Dispatch Task A to Profile dev1
   multigravity dispatch run dev1 \
     --new-worktree \
     --branch "task/backend-schema" \
     --prompt "Implement user authentication schema and unit tests in internal/auth" \
     --detach

   # Dispatch Task B to Profile dev2
   multigravity dispatch run dev2 \
     --new-worktree \
     --branch "task/frontend-api" \
     --prompt "Implement client SDK types in pkg/client matching docs/schema.json" \
     --detach

   # OR: Dispatch entire DAG stage atomically via Subtask Aggregator.
   # --repo keeps the agent workspace put, including a local repo with no origin.
   multigravity dispatch plan plan.json --repo "$REPO" --json
   # Or via REST API:
   # POST /api/v1/dispatch/plans with {"subtasks": [...], "workers": 4}
   ```
   *`dispatch run` provisions its worktree from the process working directory, so those two commands assume the shell is already in `$REPO`. A different local repository, including one with no `origin`, uses `dispatch plan --repo "$REPO"`. Using `--new-worktree` or `dispatch plan` creates ephemeral directories under `.multigravity/worktrees/<task-id>` without modifying `.gitignore` (tracked safely via `.git/info/exclude`). The plan aggregator synchronizes execution across all worktrees and returns a unified summary of diffs, additions/deletions, and checks disjoint scopes automatically.*

### Phase 4: Monitoring, Progress Tracking & Circuit Breaker
1. Track running tasks and session status:
   ```bash
   multigravity dispatch list --json
   # Or inspect specific task:
   multigravity dispatch status <task-id> --json
   ```
2. Inspect or tail execution logs if progress verification is needed:
   ```bash
   multigravity dispatch logs <task-id> --tail 50
   ```
3. **Circuit Breaker:**
   - If a task exits with `status: "failed"`:
     1. Read execution error from `multigravity dispatch logs <task-id> --tail 100`.
     2. If caused by quota/rate-limit, requeue node with an alternate healthy profile.
     3. If caused by implementation or test failure, inspect diff (`multigravity dispatch diff <task-id> --structured`), fix prompt instructions, and retry in a fresh task.
     4. If 2 consecutive failures occur on the same node, HALT DAG execution and escalate to user.

### Phase 5: In-Worktree Pre-Merge Verification
NEVER merge blindly. For each completed task node:
1. Review structured git diff:
   ```bash
   multigravity dispatch diff <task-id> --structured
   ```
   *Verify that no files outside the assigned disjoint scope were modified.*
2. Identify the worktree directory path:
   ```bash
   WT_PATH=$(multigravity worktree list --json | jq -r '(.data // .)[] | select(.task_id == "<task-id>") | .path')
   ```
3. Execute validation suite directly inside the worktree:
   ```bash
   # Run tests within the worktree context
   (cd "${WT_PATH}" && go test -v ./... && golangci-lint run)
   ```
   *Assert: All tests and linters pass with return code 0.*

### Phase 6: Topological Merge & Conflict Resolution
Merge completed branches back into the target branch following DAG topological order:
1. Checkout the integration or base branch on the main repository:
   ```bash
   git checkout main
   ```
2. Merge the verified worktree branch:
   ```bash
   git merge --no-ff "task/backend-schema" -m "feat(auth): integrate backend schema from task <task-id>"
   ```
3. Validate overall repository integrity post-merge:
   ```bash
   go test -v ./...
   bash -n multigravity install.sh uninstall.sh
   ```
4. If a merge conflict occurs:
   - Identify conflicting files via `git status --porcelain`.
   - Inspect the incoming diff from the worktree.
   - Resolve conflict preserving both contract semantics.
   - Rerun the test suite immediately.

### Phase 7: Teardown & Hygiene
1. Remove the ephemeral worktree and task records:
   ```bash
   multigravity dispatch delete <task-id> --worktree
   ```
2. Clean up any lingering git worktree metadata:
   ```bash
   multigravity worktree prune
   ```
3. Delete temporary feature branches once merged:
   ```bash
   git branch -d "task/backend-schema"
   ```

## 7. Contrast Pairs

### Task Decomposition
```text
BAD:
Assigning a single prompt "refactor the entire codebase and write new tests" to one worker.
Risk: Context exhaustion, runaway loops, unmanageable diff.

GOOD:
Decomposing into DAG:
Node 1: Extract types and interfaces (Profile: dev1, Scope: internal/types/)
Node 2: Implement business logic (Profile: dev2, Scope: internal/service/, Depends on: Node 1)
Node 3: Unit test suite (Profile: dev3, Scope: internal/service/*_test.go, Depends on: Node 2)
```

### Profile Allocation
```bash
# BAD: Dispatching task to profile without checking quota
multigravity dispatch run client-a --prompt "Generate 50 API endpoints"
# Result: Profile has 2% quota, hits rate-limit 429, fails mid-task leaving dirty worktree.

# GOOD: Inspecting quota first and selecting healthy profile
multigravity quota --json
# Profile 'worker-2' has 85% remaining in 5h window.
multigravity dispatch run worker-2 --new-worktree --prompt "Generate 50 API endpoints" --detach
```

### Workspace and local repositories
```bash
# BAD: Moving the IDE root into a local repo that has no origin, then dispatching
move_agent_to_root /home/yegear/github/polyglot-terminal
# Result: git fetch origin aborts the turn. The empty commit stays empty. No plan runs.

# GOOD: Dispatch into that repo from the current workspace
REPO=$(git -C /home/yegear/github/polyglot-terminal rev-parse --show-toplevel)
multigravity dispatch plan plan.json --repo "$REPO" --json
```

### Merge Discipline
```bash
# BAD: Merging worktree branch directly into main without testing in the worktree
git merge task/feature-x
# Result: Broken build in main branch, disrupting all concurrent agents.

# GOOD: Validating inside worktree before merge
WT_PATH=$(multigravity worktree list --json | jq -r '(.data // .)[] | select(.branch == "task/feature-x") | .path')
(cd "$WT_PATH" && go test ./... && bash -n *.sh)
# Only after 100% pass:
git merge --no-ff task/feature-x -m "feat: merge verified task/feature-x"
```

## 8. Verification Checklist

- [ ] Target repository root resolved with `git -C <target> rev-parse --show-toplevel`, and that worktree is clean (`git -C "$REPO" status --porcelain` is empty).
- [ ] Plan dispatched with `--repo "$REPO"` from the current workspace. `move_agent_to_root` was not used when `origin` is absent.
- [ ] DAG nodes have mutually disjoint file sets for all concurrent stages.
- [ ] Target profiles verified to be authenticated (`multigravity login status`) and healthy (`remaining_fraction > 0.05`).
- [ ] Ephemeral worktrees reside under `.multigravity/worktrees/` and are tracked in `.git/info/exclude`.
- [ ] Task execution monitored until `completed` status before scheduling dependents.
- [ ] In-worktree validation tests executed and passed (code 0) prior to merging.
- [ ] Merge conducted topologically with explicit commit messages.
- [ ] Post-merge regression test suite executed cleanly on the base branch.
- [ ] Completed worktrees and task records deleted via `multigravity dispatch delete <task-id> --worktree`.
- [ ] Zero auth tokens, session keys, or credentials exposed or leaked across profiles.
